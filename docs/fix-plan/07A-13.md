## Root cause
CI was authored as a build checker, not a release gate; the FFI codebase's clippy noise was left unattended, and Windows-only release packaging has no automated home.

## Fix (minimal)
1. Clippy: add `-- -D warnings` to the clippy step *or* triage the 32 warnings into `#[allow]`s with reasons and then add `-D warnings` (the fixer should prefer triage-and-then-strict; FFI naming lints get deliberate `#[allow(...)]` + a comment each).
2. Add `cargo deny check licenses bans` (config exists; fix the checker's target list if the GNU job complains).
3. Add a Linux unit-test job (cheap, catches platform-portable regressions like 07A-09's tests).
4. Add a release job on tags: run `scripts/build-windows.ps1`, upload `dist/` + SHA256SUMS as artifacts/Release assets.
- Rejected alternative: leaving clippy non-strict. With 32 existing warnings, non-strict gatelets future regressions invisible; strict-with-allows is the review's own recommendation.
