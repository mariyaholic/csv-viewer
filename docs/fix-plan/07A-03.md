# csv-viewer 07A-03 — Worker spawned without `CREATE_NO_WINDOW`: a console flashes on every full scan

- Severity: medium
- Pinned SHA verified: `eb3580da4c5820b9ca930c26de9b3f53a4839b2b`
- Status: **CONFIRMED** — `crates/csv-core/src/backend.rs:91-98` spawns `Command::new(&self.worker_path).arg("--spool-dir")…stderr(Stdio::piped()).spawn()`; repo greps for `creation_flags|CREATE_NO_WINDOW|windows_subsystem` = 0 hits; the worker is a console-subsystem exe. Because prevhost.exe has no console, Windows allocates (and shows) a new console for each child even with piped stdio.
- Size: S · Model effort: entry-level
- Depends on: none; safest kind of change to run any time (no cross-finding conflict).
- Manager sign-off: not required.

## Root cause
The spawn code was written for CI/console testing convenience and never got the Windows GUI-host attribute; nothing in the codebase sets creation flags anywhere (grep empty), so every full-scan spawn flashes a black box over Explorer.

## Fix (minimal)
- In `WorkerBackend::scan_inner` (`backend.rs:91-98`), under `#[cfg(windows)]`, before `.spawn()`: `use std::os::windows::process::CommandExt; cmd.creation_flags(0x0800_0000 /* CREATE_NO_WINDOW */);`
- Leave the non-Windows build untouched.

## Acceptance test
- Automated: the flag is not observable in-process; assert structurally with a tiny unit test that builds the `Command` and (on Windows) reflects `creation_flags` via a debug callback… Go-style introspection isn't available in Rust std — the practical automated gate is: `cargo clippy` has no catch. Accept a smoke-level automation: spawn the worker from a Rust test with a console-less parent (test runner) and assert stdout pipe still works (the flag must not interfere with piped stdio).
- Manual on this PC (decisive): press `F` (full-scan refresh) in the preview pane; verify **no** console window appears. Repeat ~5 times with rapid F presses.

## Risk / blast radius
- One attribute on one spawn. Watch: `CREATE_NO_WINDOW` with piped stdio is standard practice; reading `stderr`/`stdout` pipes continues to work. No other finding interacts.
