# csv-viewer 07A-01 — Temp spool is not writable from a Low-IL prevhost, so the preview likely fails outright on real Windows

## Root cause
The preview handler does its work in the host's environment (prevhost, Low-IL by default) but its implementation assumes a normal process context: `%TEMP%` is not writable at Low integrity without an integrity label, so the first stream copy fails and `DoPreview` returns `E_FAIL` (`windows.rs:638-641`) before any window appears — the user sees only "can't preview". Wine has no integrity levels, so the whole failure was invisible to every Wine round-trip.

## Fix (pick ONE; both are legitimate — the alternative we reject is "hope Low-IL goes away")
1. **Opt out of Low IL (PowerToys-style, documented route):** add a `REG_DWORD` write path (`ExpectedValue` gains a DWORD variant; `write_value`/`read_value` at `windows.rs:1228-1331`) and register `DisableLowILProcessIsolation=1` under our `CLSID` key; ownership-checked removal in `unregister`'s plan (mirror of the current rollback logic). Slightly reduces the safety posture (preview runs Medium IL).
2. **Keep Low IL (safer, more work):** spool to `FOLDERID_LocalAppDataLow` (`SHGetKnownFolderPath`, new extern in `windows.rs`'s user32/advapi32/shell32 block) with the head kept in memory (66 KiB is not affected — only the full-scan spool moves).
- Whatever the fixer picks, the head path (`session.rs:115-145`) stays as-is; only the full-scan temp area is at stake.

## Acceptance test
- Automated (variant 1): extend the registry Fake mocks (`registration.rs:242-265`) with a DWORD knob; test `register_plan_writes_disable_lowil_dword_and_unregister_removes_it` in the `TestRegistry` suite. Fails before (no such value), passes after.
- Automated (variant 2): can't be unit-tested (COM known-folder call); cover the temp-root selection with a small test that `ShGetKnownFolderPath` resolves and the returned dir is under `LocalLow`/home — the real assertion is manual below.
- **Manual on this PC (the decisive check):** register, select a `.csv` in Explorer. Preview must render. Open Process Explorer → `prevhost.exe` → Integrity column: with variant 1 it reads Medium; with variant 2 it must still read Low, and `%TEMP%\csv-viewer-*` must **not** appear (spool lands in LocalLow instead). Also place a fake read-only `%TEMP%` Nice? no — don't mutate %TEMP%; the Low-IL check is the real one.

## Risk / blast radius
- Variant 1 changes the security boundary — incompatible with any future sandboxing of the preview path; it documents nothing wrong on the way out though (read Merkel plan).
- Variant 2 touches only the temp path decision; bigger FFI surface (SHGetKnownFolderPath).
- Registry-plan changes interact with 07A-07 (register/CLI work) and 07A-08 (unregister residue) — the three should be a planned sequence in one session rather than four fixer sessions racing the same `windows.rs` registry block: **order 07A-01 → 07A-07 → 07A-08**.
- 07A-02 rebuilds on whatever 01 leaves stable.
