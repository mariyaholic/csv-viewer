# csv-viewer 07A-11 — Full-scan key is nearly unreachable: `'f'` compares against VK codes (matches Numpad-6), the pane never takes focus on click, accelerators never forwarded

- Severity: low
- Pinned SHA verified: `eb3580da4c5820b9ca930c26de9b3f53a4839b2b`

## Root cause
Two different bugs stacked: comparing an ASCII letter against a VK key code (so Numpad-6 triggers and the F key never does), and no keyboard/focus integration with the host (no click-to-focus, no site/frame forwarding), making the *intended* F key unreachable anyway.

## Fix (minimal, in two separable sub-sets)
1. **Hotkey subset (S):** in `preview_window_proc` (`windows.rs:792-831`) compare against `VK_F (0x46)` on `WM_KEYDOWN`; add `WM_MOUSEACTIVATE` → `SetFocus(hwnd)` (or `WM_LBUTTONDOWN` → `SetFocus`) arm so clicking the pane focuses it.
2. **Site/frame subset (M):** implement `IObjectWithSite` (new vtable/struct mirroring the COM pattern; QI entry in `query_preview_interface` `:344-365`), QI the site for `IPreviewHandlerFrame` in `SetSite`, and forward unhandled keys in `preview_translate_accelerator` (`:546-551`) via that frame.
- Optional third: prefer `WM_DPICHANGED`-style message mapping only if the Manager wants more keys; keep F and forward-only as the spec.

## Acceptance test
- Unit (subset 1): a fake-window-proc message table test asserting `WM_KEYDOWN` with wparam 0x46 triggers the scan path (extract the key handler); fails before (0x46 never matched), passes after.
- Unit (subset 2): with a fake IPreviewHandlerFrame, `TranslateAccelerator` on an unhandled key forwards it (mirrors parquet L5's harness).
- Manual on this PC (XR-2): click the pane, press `F` — full refresh starts; `Tab` moves focus back out (subset 2 only).

## Risk / blast radius
- Subset 1 alone is trivial and safe. Subset 2 is a COM surface addition (same blast radius shape as parquet L5): new QI entries + refcount bridging; keep implementation pattern identical to the repo's existing interface structs (`windows.rs:291-323`).
- No dependency on other findings; the site work pairs with 07A-06 (both under the COM/lifecycle hat).
