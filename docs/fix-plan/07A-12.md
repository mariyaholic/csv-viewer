## Root cause
The test suite grew around the product seams that exist today instead of the seams the architecture cares about (head-promptness, worker integration), and one convenience skip became a permanently-green hole.

## Fix (minimal)
1. Extract the `do_preview` source pipeline (`windows.rs:618-652`) into a platform-neutral function (it already takes a reader; make the copy+head logic independent of window/COM stubs) and test *that*: promptness via the slow reader, cap behaviour via 07A-09's test, single-copy via a counting reader.
2. Make the worker-integration skip honest: fail when `CI` env is set and the binary is absent (compile the binary in the CI job instead); otherwise `#[ignore]` it so the count is truthful.
3. Keep `windows.rs`'s existing unit test(s); add none for FFI scope here (07A-05/06/10/11 add their own).

## Acceptance test
- The changes *are* test craft. Fails-before target: `cargo test -p csv-preview` with no worker built must **fail or report ignored**, not "ok" — trivially checkable by running that command (verify current greem state first, then the new behaviour).
- Promptness test: with the extraction from 07A-02, `slow_stream_preview_still_returns_a_head` is retargeted at the extracted function and becomes meaningful on Linux/Windows both.

## Risk / blast radius
- Test-only + one extraction function (whose existence is really 07A-02's deliverable). If 07A-02's fixer implements the pipeline extraction, this spec collapses into "retarget + fix the skip".
