# csv-viewer 07A-02 — `DoPreview` blocks the host STA for a whole-file copy (up to 4 GiB), then copies it again

- Severity: high
- Pinned SHA verified: `eb3580da4c5820b9ca930c26de9b3f53a4839b2b`
- Status: **CONFIRMED** — `preview_do_preview` (`windows.rs:618-652`) fully copies the stream synchronously before `PreviewSession::start`: `session.rs:139` `io::copy(&mut source.take(limit.saturating_add(1)), &mut file)?` with `max_spool_bytes: 4 GiB` (`session.rs:110`); the spool thread then runs `write_spool` (`session.rs:464-512`) which writes a **second** file (`File::create` `:472`) and calls `file.sync_data()` (`:510`) regardless of whether the user ever asks for a full scan. Docs contradiction confirmed (`ARCHITECTURE.md:21` "show first rows promptly"; `TESTING.md` "Huge file: preview appears promptly"; `STATUS.md:25` hedges "can delay the host"). Regression introduced by Terra fix `7225af3`.
- Interactive cost: while the STA is blocked, `Unload` and a new `DoPreview` cannot run — selection-change (cancel) is impossible during the copy.
- Size: L · Model effort: strongest available (COM-threading/cancellation design)
- Depends on: **07A-01 first** (settles the security/spool shape this rebuilds on); 07A-12 (the slow-stream test) is its acceptance scaffolding, not a blocker.
- Manager sign-off: not required. Policy flags: none.

## Root cause
Terra's apartment-violation fix (`7225af3`) removed the unsafe cross-thread stream usage by copying everything eagerly *on the host's own thread* — trading a crash class for a blocking class. The architecture's intent (bounded, prompt head, on-demand full scan) got flattened into one synchronous copy per selection.

## Fix (minimal but architectural)
1. `preview_do_preview` reads only the **head bytes** (256 KiB) synchronously — enough to render the first screen — then starts `PreviewSession::start` immediately; the rest of the copy never runs on the STA.
2. Full scan on demand: when `F` is pressed, copy in **bounded chunks on the STA driven by messages/timers** so the pump stays live (`Unload` and selection-change can cancel). Alternative acceptable here: marshal the stream properly (`CoMarshalInterThreadInterfaceInStream` or the GIT) and read it on the existing worker thread — but then the whole 07b-M1-style cancellation/marshal design applies (matches how parquet-viewer M1 will be fixed); pick whichever the fixer can implement correctly inside this repo's existing `IInitializeWithStream` plumbing.
3. Pass the already-copied spool file to the session as its spool (no second copy): `write_spool` consumes the delivered head + stream chunks; delete the duplicate `File::create` write.
- Whatever shape is chosen, `Unload` must be able to interrupt (this decides between the chunked-STA and marshalled-worker variants — the marshal variant is excellent if implemented once rather than half-way).

## Acceptance test
- Unit (platform-neutral, after extracting the pipeline — 07A-12's job): `head_only_stream_preview_returns_promptly` — a slow-but-infinite stream (NeverReader) fed through the extracted `do_preview` path must return a head in < 1 s without consuming the whole stream. Fails before (would consume 4 GiB before returning), passes after.
- Windows integration in `tests/session.rs` once the spool relay exists: full-scan button stream copied exactly once (count writes via a counting Reader).
- Manual on this PC: select a 2 GB CSV; first pane paints in ~1-2 s; change selection during scan → new file previews immediately. Watch `%TEMP%`: growth caps at the head + on-demand spool, no 2× file size, no fsync unless a full scan ran.
