## Root cause
The document contract (warn before system-setting changes) and the code (silent eprintln under a window-less regsvr32) were never joined; and the preflight read only the per-user hive, which cannot see machine-wide conflicts.

1. CLI register path: extend `crates/csv-viewer/src/args.rs::Options::parse` (`:24`, arms near `:43`) with `--register`/`--unregister`/`--force`. The CLI path prints `REGISTRATION_WARNING` (`registration.rs:19`) and asks for confirmation before calling `register_module` (prompts on stdin; no GUI needed for v1).
2. Preflight vendored-hives: in `register_module`'s conflict check (`windows.rs:1123-1148`), also read the merged `HKEY_CLASSES_ROOT` view (same key path; new Windows constant + extern in the advapi32 block — the fixer adds `HKEY_CLASSES_ROOT` and reads `HKEY_CLASSES_ROOT\.csv\ShellEx\{8895…}` for a foreign CLSID); refuse without `--force` when a foreign handler exists, printing a **visible** message (when driven via regsvr32, keep the refusal silent-out? no — the code first, and regsvr32 failures surface as error dialogs).
